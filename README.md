# NoSleep

Локальное приложение macOS с независимыми переключателями:

- не позволять Mac засыпать;
- не гасить экран при бездействии.

Окно открывается из Dock или меню значка чашки. Закрытие окна оставляет приложение в фоне. «Включить всё / Выключить всё» включает или отключает обе защиты питания. «Выйти» снимает защиту и завершает приложение. Выбранные переключатели сохраняются между запусками.

При выключении или перезапуске Mac NoSleep спрашивает подтверждение до снятия защиты. «Отмена» (также Enter или Escape) сохраняет приложение и защиту, отменяя эту попытку выключения/перезапуска. «Продолжить» снимает защиту и разрешает завершение. Обычный выход через меню, Dock или ⌘Q и выход из учётной записи остаются без диалога. Если снять защиту не удалось, приложение остаётся открытым и показывает ошибку.

## Сборка из исходников

Нужны macOS 14+ и Apple Command Line Tools. Приложение разработано и проверено на macOS 27.0.1 / Apple Silicon; остальные версии отдельно не проверены.

```sh
./scripts/build.sh
open build/NoSleep.app
```

### Локальная подпись разработчика

Для проверки обновлений можно создать отдельную локальную identity и подписать отдельную копию приложения:

```sh
python3 scripts/sign-local-development.py ensure
NOSLEEP_BUILD_APP=build/local-signed/NoSleep.app ./scripts/build.sh
python3 scripts/sign-local-development.py sign build/local-signed/NoSleep.app
```

Для следующих сборок и DMG можно явно использовать ту же сохранённую подпись:

```sh
NOSLEEP_SIGNING_CONFIG="$HOME/Library/Application Support/NoSleep-Development/signing-identity-v2.json" \
NOSLEEP_BUILD_APP=build/local-signed/NoSleep.app ./scripts/build.sh
NOSLEEP_SIGNING_CONFIG="$HOME/Library/Application Support/NoSleep-Development/signing-identity-v2.json" \
./scripts/package-dmg.sh
```

Без этой настройки обычные проверки используют ad-hoc подпись. Если подпись выбрана явно, отсутствие файла или ошибка подписания останавливают сборку; перехода на другую подпись нет. Это сохраняет выбранную идентичность приложения при обновлениях. Доступ к старой записи и разрешение macOS всё равно подтверждаются отдельными проверками.

Связка ключей пользователя должна быть разблокирована. Закрытый ключ создаётся в отдельной Связке ключей, запрещён к экспорту и доступен только `codesign`. Пароль этой Связки хранится отдельной записью с доступом только для системного `security`; он не передаётся через аргументы, файлы или логи. Существующие ключи, записи VPN, настройки доверия и разрешения macOS не меняются. Файлы из `~/Library/Application Support/NoSleep-Development` не включаются в DMG или репозиторий. Эта подпись не является Developer ID или нотарификацией Apple.

```sh
python3 tests/keychain_identity_acceptance.py --contract-only
python3 tests/keychain_identity_acceptance.py --private-keychain-experiment
```

Второй тест использует настоящие API macOS и новую временную Связку ключей: проверяет обновление двух сборок с одной подписью и отказ сборкам с другой подписью, затем удаляет свои записи и ключи. Приложение в тесте не получает пароль Связки и не меняет ACL. Перенос старой записи из сборки с ad-hoc подписью, доступ к пользовательской Связке и сохранение разрешения «Универсальный доступ» проверяются отдельно.

## Первый запуск

Перенесите приложение в «Программы», откройте его и нажмите **«Настроить NoSleep»**. macOS один раз запросит пароль администратора. После подтверждения запрет сна включится автоматически. Если доступ уже настроен, повторного запроса нет. Защита экрана включается отдельной галочкой.

Встроенная настройка разрешает только текущей учётной записи две операции `pmset -a disablesleep 1` и `pmset -a disablesleep 0` без повторного пароля. Остальные команды администратора не разрешаются. Правило создаётся как `/private/etc/sudoers.d/nosleep_UID`. Подготовленный файл проверяется `visudo`; существующее правило не перезаписывается. Административный пароль запрашивает macOS, приложение его не читает и не сохраняет.

Нет необходимости запускать Терминал или отдельный файл. `scripts/install-power-helper.command` сохранён в репозитории только как дополнительный способ для опытных пользователей и не входит в DMG.

Проверка сна работает каждую секунду в отдельной очереди. Приложение ждёт подтверждения macOS после переключения и сохраняет защиту от бездействия при неудачном восстановлении. Корпоративные настройки могут ограничивать режим работы.

## Диагностика

Типизированные локальные журналы ограничены 200 МБ и семью днями. Кнопка «Отчёт…» сохраняет ZIP вручную; секреты, сетевые настройки и системные журналы не экспортируются. Подробности: [диагностика](docs/diagnostics.md).

## Проверки

Все воспроизводимые проверки хранятся в этой репозитории вместе с исходниками. [Общий запуск, CI и инструкция ручной приёмки](docs/testing.md) перечисляют сценарии и их ограничения. Отчёты и временные снимки остаются в игнорируемых каталогах.

```sh
./scripts/test.sh
./scripts/test.sh --ci
./scripts/test.sh --local
```

Проверяются независимые переключатели, задержка применения настроек, ошибки, восстановление после сброса, сохранение idle assertion при неуспешном восстановлении и работа проверки при занятом потоке интерфейса.

Общий runner собирает отдельную копию в `build/regression/NoSleep.app`, проверяет контракт безопасности и не меняет работающую сборку или Cisco. `--ci` дополнительно проверяет реальный лимит 200 МБ и RSS; `--local` включает нативный UI E2E с изолированной моделью питания. GitHub CI запускает эти проверки на Apple Silicon и Intel и проверяет DMG перед релизом. Настоящие переключатели проверяются отдельным явным сценарием. Успешный удалённый запуск workflow ещё не подтверждён.

Проверка реального приложения (меняет его переключатели и включает обе защиты в конце):

```sh
open build/NoSleep.app
python3 tests/live_acceptance.py
```

Тест проверяет выключение, отдельную защиту экрана, сохранение выбора после выхода, открытие окна, снятие запрета при выходе и восстановление после внешнего сброса. Требуется заранее согласованное правило команд питания. Физическое закрытие крышки выполняется пользователем отдельно.

Состояние и ограниченные типизированные журналы находятся в `~/Library/Application Support/NoSleep/` (`state.json`, `ui.json`, `diagnostics/events-*.jsonl`). Старый свободный журнал удаляется при обновлении; в поддержку отправляется только созданный через кнопку ZIP.

Проверка отдельной сборки без изменения установленного приложения:

```sh
NOSLEEP_BUILD_APP="$PWD/build/candidate/NoSleep.app" ./scripts/build.sh
build/candidate/NoSleep.app/Contents/MacOS/NoSleep --self-test
python3 tests/safety_contract.py build/candidate/NoSleep.app
python3 tests/ui_acceptance.py --no-screenshots
```

NoSleep управляет только защитой сна и экрана. В приложении нет сетевого наблюдения, подключения, VPN-настроек или доступа к сохранённым паролям. Старые настройки и записи Связки ключей не читаются и автоматически не удаляются.

## Удаление

Сначала нажмите «Выйти», затем удалите приложение. Если правило `nosleep_UID` было создано этим установщиком и больше не нужно, администратор может удалить только `/private/etc/sudoers.d/nosleep_UID`.

## DMG для передачи другим пользователям

```sh
python3 -m pip install --target build/packaging-python -r scripts/requirements-dmg.txt
./scripts/package-dmg.sh
python3 tests/dmg_acceptance.py build/NoSleep-universal.dmg
```

Универсальная сборка для Apple Silicon и Intel требует macOS 14+. Окно образа содержит два значка: NoSleep слева и ссылку «Программы» справа, между ними стрелка. Файла инструкции в образе нет. Нужен администратор для первоначальной настройки сна. Без Developer ID и notarization запуск на другом Mac может потребовать разрешения «Открыть всё равно» в системных настройках. Intel-версия собрана, но запуск на Intel отдельно не проверен. Зависимости Python используются только при сборке DMG, установленному приложению они не нужны.

Проверка интерфейса первого запуска без административных изменений: `NOSLEEP_APP=/путь/NoSleep.app python3 tests/onboarding_acceptance.py`. Она моделирует отсутствие настроенных прав и проверяет распознавание уже существующего правила. На новом аккаунте установка через системный диалог проверяется пользователем отдельно.

Версия 3.4.5 включает подтверждение системного выключения/перезапуска и завершённые проверки автоматического релиза; нативное доказательство регрессии выполняется в macOS-задачах CI.
