# NoSleep

Локальное приложение macOS с независимыми переключателями:

- не позволять Mac засыпать;
- не гасить экран при бездействии;
- показывать состояние установленного Cisco VPN.

Окно открывается из Dock или меню значка чашки. Закрытие окна оставляет приложение в фоне. «Включить всё / Выключить всё» включает или отключает функции NoSleep, включая наблюдение. Соединение Cisco остаётся под управлением Cisco. «Выйти» снимает защиту и завершает приложение. Выбранные переключатели сохраняются между запусками.

## Сборка и запуск

Нужны macOS 14+ и Apple Command Line Tools. Приложение разработано и проверено на macOS 27.0.1 / Apple Silicon; остальные версии отдельно не проверены.

```sh
./scripts/build.sh
open build/NoSleep.app
```

## Первый запуск

Перенесите приложение в «Программы», откройте его и нажмите **«Настроить NoSleep»**. macOS один раз запросит пароль администратора. После подтверждения запрет сна включится автоматически. Если доступ уже настроен, повторного запроса нет. Защита экрана включается отдельной галочкой.

Встроенная настройка разрешает только текущей учётной записи две операции `pmset -a disablesleep 1` и `pmset -a disablesleep 0` без повторного пароля. Остальные команды администратора не разрешаются. Правило создаётся как `/private/etc/sudoers.d/nosleep_UID`. Подготовленный файл проверяется `visudo`; существующее правило не перезаписывается. Административный пароль запрашивает macOS, приложение его не читает и не сохраняет.

Нет необходимости запускать Терминал или отдельный файл. `scripts/install-power-helper.command` сохранён в репозитории только как дополнительный способ для опытных пользователей и не входит в DMG.

Проверка сна работает каждую секунду в отдельной очереди. Приложение ждёт подтверждения macOS после переключения и сохраняет защиту от бездействия при неудачном восстановлении. Корпоративные настройки могут ограничивать режим работы.

## Рабочий VPN: безопасный режим 3.1

NoSleep переиспользует встроенное восстановление сессии Cisco и не запускает собственные подключения. Если Cisco установлен, наблюдение доступно сразу; пароль в NoSleep вводить не нужно. Явное отключение сохраняется. Приложение показывает политику AutoReconnect, но не меняет корпоративный профиль. При полном завершении сессии Cisco может потребовать новый вход: его выполняют в самом Cisco, кнопка «Открыть Cisco» только открывает проверенный официальный клиент.

Опрос — фиксированная локальная команда `vpn -s state` без входящих данных, не чаще раза в минуту. Проверяется подпись Cisco. Таймаут — 6 секунд, ответ — максимум 16 KiB. Неизвестный ответ/ошибка останавливает наблюдение, в том числе после перезапуска, до явного выключения и включения тумблера. NoSleep не читает и не записывает VPN-пароли в Связке ключей, не отправляет данные входа, не запускает connect/disconnect и не перезапускает Cisco. Обрыв/повторная авторизация обслуживаются нативным клиентом.

Откройте «Диагностика…» для ZIP: максимум 1 MiB логов за семь дней, без паролей, логинов, адресов VPN, сырого вывода и системных журналов. Экспорт вручную; автоматической отправки нет. Подробности: [диагностика](docs/diagnostics.md), [разбор инцидента и принципы](docs/vpn-incident.md).

## Проверки

```sh
./scripts/test.sh
```

Проверяются независимые переключатели, задержка применения настроек, ошибки, восстановление после сброса, сохранение idle assertion при неуспешном восстановлении и работа проверки при занятом потоке интерфейса.

Проверка реального приложения (меняет его переключатели и включает обе защиты в конце):

```sh
open build/NoSleep.app
python3 tests/live_acceptance.py
```

Тест проверяет выключение, отдельную защиту экрана, сохранение выбора после выхода, открытие окна, снятие запрета при выходе и восстановление после внешнего сброса. Требуется заранее согласованное правило команд питания. Физическое закрытие крышки выполняется пользователем отдельно.

Состояние и ограниченные типизированные журналы находятся в `~/Library/Application Support/NoSleep/` (`state.json`, `ui.json`, `diagnostics/events-*.jsonl`). Старый свободный журнал удаляется при обновлении; в поддержку отправляется только созданный через кнопку ZIP.

Проверки безопасной новой сборки с восстановлением установленного приложения и исходных переключателей:

```sh
./scripts/build.sh --universal
build/NoSleep.app/Contents/MacOS/NoSleep --self-test
build/NoSleep.app/Contents/MacOS/NoSleep --verify-cisco-observer
python3 tests/safety_contract.py build/NoSleep.app
python3 tests/safety_live_acceptance.py
```

Локальный E2E требует заранее работающего Cisco VPN и настроенного питания. Проверяет фактические переключатели, состояние/политику Cisco, отмену своего опроса, сохранение отключения, повторный запуск, ZIP и неизменность рабочего соединения/профиля/агента. Не разрывает VPN, не вводит пароль и не проверяет реальную новую авторизацию. Команда smoke показывает только нормализованное состояние и результат проверки подписи GUI. На Intel выполнена сборка; запуск отдельно не проверен.

## Удаление

Сначала нажмите «Выйти», затем удалите приложение. Если правило `nosleep_UID` было создано этим установщиком и больше не нужно, администратор может удалить только `/private/etc/sudoers.d/nosleep_UID`.

## DMG для передачи другим пользователям

```sh
python3 -m pip install --target build/packaging-python -r scripts/requirements-dmg.txt
./scripts/package-dmg.sh
python3 tests/dmg_acceptance.py build/NoSleep-universal.dmg
```

Универсальная сборка для Apple Silicon и Intel требует macOS 14+. Окно образа содержит два значка: NoSleep слева и ссылку «Программы» справа, между ними стрелка. Файла инструкции в образе нет. Нужен администратор для первоначальной настройки сна. Без Developer ID и notarization запуск на другом Mac может потребовать разрешения «Открыть всё равно» в системных настройках. Intel-версия собрана, но запуск на Intel отдельно не проверен. Зависимости Python используются только при сборке DMG, установленному приложению они не нужны.

Проверка интерфейса первого запуска без административных изменений: `NOSLEEP_APP=/путь/NoSleep.app python3 tests/onboarding_acceptance.py`. Она моделирует отсутствие настроенных прав и проверяет распознавание уже существующего правила. На новом аккаунте установка через системный диалог проверяется пользователем отдельно.
